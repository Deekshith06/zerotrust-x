# ZeroTrust-X

ZeroTrust-X is an evidence-led security operations platform for synthetic, educational Track 2 telemetry. It normalizes IAM, firewall, endpoint, and identity records; preserves data-quality lineage; produces deterministic detections and explainable risk; and provides role-scoped investigation workflows.

> This project surfaces suspicious behavioral patterns. It does not prove malicious intent or identify real attackers.

## Quick start

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m zerotrust_x.cli ingest \
  --input-dir track2_cybersecurity_dataset_files \
  --output-dir data/processed \
  --quarantine-dir data/quarantine
.venv/bin/python -m uvicorn zerotrust_x.web:app --host 127.0.0.1 --port 8000
```

Open `http://127.0.0.1:8000/`.

## Current P0/P1/P2 capabilities

- Reproducible CSV, JSON, and XLSX ingestion.
- Provenance-preserving normalization and explicit quarantine reason codes.
- Parquet artifacts: events, detections, user risk, and quality report.
- Deterministic authentication and endpoint detection rules.
- Explainable 0–100 risk scores with evidence IDs.
- FastAPI query surface and responsive SOC command dashboard.
- Deterministic investigation graph with grounding validator.
- Read-only role controls: `EMPLOYEE`, `SOC_ANALYST`, `SOC_ADMIN`.
- Append-only local audit log for sensitive analyst actions.
- Timeline and relationship graph APIs.
- Vendor-neutral adapter protocol for future source onboarding.
- Process-local measured metrics and explainable baseline anomaly scores.

## Local authentication adapter

The current local deployment uses an `X-Demo-Token` compatibility header only because OIDC/JWKS is not yet wired:

```text
employee-demo  → EMPLOYEE / EMP10001 only
analyst-demo   → SOC_ANALYST
admin-demo     → SOC_ADMIN
```

These tokens are not production authentication. A deployment must replace them with OIDC/SSO, secure session handling, secret rotation, and tenant-aware authorization.

## Engineering guarantees

- Raw source files are not modified by ingestion.
- Invalid values retain their raw representation and source reference.
- The LLM is not the source of truth for telemetry or risk.
- No arbitrary SQL or shell execution is exposed through API tools.
- Investigation reports are rejected when they cite unsupported IDs.
- Generated artifacts are read-only to downstream API consumers; source data is never modified by ingestion.
- Metrics are measured process-local observations, not fabricated production claims.

## Industrial console

The dashboard is a read-only SOC analyst console with dense operational views for overview, investigations, evidence timeline, entity graph, data quality, and employee self-scope activity. The entity graph is rendered from actual event relationships and exposes node-level provenance; it does not infer or invent relationships.

## Readiness, manifest, and evaluation

```text
GET /health       process health
GET /ready        artifact readiness
GET /api/manifest source/output hashes and quality counts (analyst/admin)
```

`data/processed/manifest.json` is generated by ingestion and supports deterministic rerun comparisons. Generated v2 artifact directories are validated for manifest schema, output hashes, required Parquet columns, and quality-count consistency before readiness or API consumption. The checked-in legacy artifact set remains immutable and intentionally reports not-ready until separately migrated. See `docs/evaluation.md` for the acceptance checks and the distinction between deterministic rules, derived anomaly ranking, and verified threat labels. The Track 2 point-by-point evidence matrix and weighted scorecard are in `docs/track2-alignment.md`.

## Tests

```bash
.venv/bin/pytest -q
.venv/bin/ruff check src tests
```

The dataset is synthetic and does not provide verified ground truth. Evaluation therefore distinguishes deterministic rule checks, reproducible artifact manifests, local recovery verification, bounded local benchmark measurements, and qualitative analyst review. See `docs/status-matrix.md` for the complete implemented-local versus deployment-dependent control boundary. Docker assets are included for the local read-only dashboard path; replace local authentication with OIDC/SSO before any production deployment.
